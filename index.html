Architecture

不是三个模型轮流聊天，而是一套有职责边界的研发组织。

最核心的设计是把“规格、决策、执行、证据、验证和最终控制权”拆成不同角色。

Specification

Spec Kit

先把需求、约束与验收标准变成稳定规格，让长任务不依赖聊天上下文临时猜测。

Task Contract

Task 01–99

把复杂目标拆成有稳定身份、明确边界、可追踪且可验收的研发任务单元。

Reasoning

GPT · Brain / Reviewer

理解任务事实、判断下一步、审查执行证据，并决定继续、修订、暂停或完成。

Execution

Claude Code / Codex · Executor

真正读取仓库、修改文件、增加测试、运行允许命令并返回执行证据，但不拥有自行降低验收标准的权力。

Control Plane

Verification · Approval · Recovery

用确定性检查验证事实，在关键节点保留人工控制，并让中断任务从可信进度继续，而不是无条件重开。

Spec 定义目标，Brain 做判断，Executor 做执行，Verification 给证据，人类保留关键控制权。

Engineering Principles

AI 可以很强，但强能力更需要工程约束。

Spec before execution

先定义“要做什么”和“什么算做完”，再让 Agent 进入仓库。

Evidence over claims

Executor 可以提交答卷，但不能仅凭一句“done”给自己判满分。

Hard boundaries

允许路径、禁止路径、约束和验收标准是执行边界，不是建议。

Deterministic verification

测试、类型检查、构建和仓库检查交给更稳定的确定性工具。

Human at critical decisions

系统必须有能力安全停下来，而不是在信息不足时强行自动化。

Recover instead of restart

长任务中断后优先保留已验证进度，让 continuation 真正延续已有工作。
